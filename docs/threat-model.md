# Threat model

| Threat / surface                         | Impact                            | Mitigations in this project                                                         | Residual risk                                                                                 |
| ---------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Credential stuffing or password guessing | Account takeover                  | Argon2id, auth rate limiting, generic credential errors, optional TOTP              | Shared global limiter is not distributed; no breached-password check                          |
| Stolen access token                      | Unauthorized actions until expiry | 15-minute access token default, TLS requirement, role/object checks                 | No access-token denylist; production secret rotation needed                                   |
| Refresh token theft/replay               | Persistent session takeover       | Random opaque token, only hash persisted, single-use transactional rotation, logout | Sessions are not device-bound; replay detection/account-wide revocation policy limited        |
| Concurrent slot booking                  | Double booking                    | Serializable transaction and atomic conditional slot claim                          | Requires PostgreSQL; clients must handle 409 and retry safely                                 |
| IDOR across consultation/prescription    | Medical data disclosure           | Resource ownership checked on consultation and prescription reads                   | Requires ongoing review for every new endpoint                                                |
| Malformed or oversized request           | DoS/injection                     | Zod schemas, 32 KB JSON cap, Helmet, parameterized ORM                              | Rate limiting needs trusted proxy/IP and distributed store at scale                           |
| Secret or health data in logs            | Privacy incident                  | Pino redaction; audit stores no prescription content                                | Application exceptions must be reviewed for future data leakage                               |
| Database compromise or ransomware        | Broad data loss/disclosure        | Relational access boundaries and documented encrypted backups                       | Encryption, network controls, key custody and restore process are deployment responsibilities |
| Dependency supply-chain compromise       | Code execution/data exfiltration  | Lockfile and CI dependency installation                                             | CI dependency scanning is not yet configured; pin/actions review required                     |
| Insider modifies audit history           | Compliance evidence loss          | Audit records and access is admin-only via API                                      | Same database role can modify logs; use external immutable sink in production                 |

Data classification: credentials and TOTP secrets are restricted; identity, consultation and prescription data are sensitive health information; operational metrics are low sensitivity when labels avoid user identifiers. Attack surfaces are public REST routes, auth/session endpoints, database, container image, CI dependencies, and operator access.
